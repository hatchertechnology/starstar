# Print Library — Phase 1 (Library Store) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Operators upload sliced print files into a starstar library stored on disk, and everyone can list them, see their preview and slicer details read from the file itself, download them, and (admins) delete them — from the web UI, CLI and MCP.

**Architecture:** File bytes live under `STARSTAR_LIBRARY_DIR` (content-addressed by SHA-256, written to `tmp/` then renamed); the catalog lives in Postgres (migration v3). A parser reads bgcode blocks / ASCII G-code comments for metadata and the preview, converting QOI to PNG. New `library` module with role-checked service functions, thin axum routes, MCP tools, CLI commands and Nuxt pages, following the existing `printers::files` patterns.

**Tech Stack:** Rust (axum, sqlx/Postgres, sha2, tempfile, new `image` crate with `png`+`qoi` features only), Nuxt 4/Vue 3, vitest, Kustomize on Thor (`zfs-local` PV).

**Spec:** `docs/superpowers/specs/2026-11-27-print-library-design.md` (phase 1 of "Delivery order").

## Global Constraints

- Phase 1 only: no filament records, batches, printer copies, or backups.
- Storage: `STARSTAR_LIBRARY_DIR` (default `library`, relative to the working directory); subdirectories `blobs/<sha[0..2]>/<sha[2..4]>/<sha>`, `thumbs/<sha>.png`, `tmp/`. Created at startup; the API refuses to start if the directory is not writable (message names the variable).
- Accepted kinds: `.bgcode` and `.gcode` (case-insensitive extension of the uploaded name); anything else → 400 `only .bgcode and .gcode files can be added to the library`.
- Upload size limit: the existing `max_upload_bytes` (`STARSTAR_MAX_UPLOAD_MB`, default 512); `Content-Length` required (411), over the limit → 413, same messages as printer uploads.
- Versions: per `name`, starting at 1. Re-uploading a name whose **latest** version has the same SHA-256 returns that version with 200 and stores nothing new; otherwise a new version, 201.
- Ids: `BIGINT GENERATED BY DEFAULT AS IDENTITY` (matches `users.id`); the spec's "uuid" is replaced by this — ruling recorded at execution.
- Roles: list/get/preview/download → Viewer; upload → Operator; delete → Admin.
- Preview responses: `image/png`, `Cache-Control: private, max-age=300`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox; frame-ancestors 'none'` (same as the thumbnail route).
- Download responses: `Content-Type: application/octet-stream`, `Content-Disposition: attachment; filename*=UTF-8''<percent-encoded name>`, `nosniff`.
- A parse failure never rejects an upload: `parsed = false`, empty meta, no preview.
- The display name is never used as a filesystem path.
- Repo rules: commit on `main` per task, never push without the user.

## Review Focus

1. An upload cut off mid-stream (client disconnect, length mismatch) must leave no blob, no catalog row, and no file in `tmp/`. → Task 2 test `aborted_write_leaves_nothing`, Task 3 test `short_body_stores_nothing`.
2. Two uploads of the same new name at the same time must both succeed with versions 1 and 2, not a 500 from the unique constraint. → Task 2 test `concurrent_same_name_gets_distinct_versions`.
3. Names like `../../etc/x.gcode`, `a/b.bgcode`, `café #1?%.bgcode` are stored as display names only; files land only under `blobs/`. → Task 3 test `hostile_names_stay_display_names`.
4. Deleting one of two versions that share a blob keeps the blob and preview; deleting the last reference removes both. → Task 2 test `blob_removed_only_with_last_reference`.
5. A `.bgcode` with a corrupt block (bad CRC or truncated) or ASCII G-code with no slicer comments is stored with `parsed = false`, not rejected. → Task 1 tests `corrupt_bgcode_is_unparsed` and `plain_gcode_is_unparsed`.

### Task 2: Library storage and catalog

**Files:**
- Create: `crates/api/src/library/store.rs`

- Test: unit tests in `store.rs` (need `STARSTAR_TEST_DATABASE_URL`, like `store.rs` tests)

**Interfaces:**
- Migration v3 `library`:
  ```sql
  CREATE TABLE library_files (
      id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      name        TEXT NOT NULL,
      version     INTEGER NOT NULL,
      sha256      TEXT NOT NULL,
      size        BIGINT NOT NULL,
      kind        TEXT NOT NULL,
      meta        JSONB,
      parsed      BOOLEAN NOT NULL,
      has_preview BOOLEAN NOT NULL,
      uploaded_by TEXT NOT NULL,
      uploaded_at BIGINT NOT NULL,
      UNIQUE (name, version)
  );
  CREATE INDEX library_files_sha256 ON library_files (sha256);
  ```
- `LibraryFile` (shared, serde): `id: i64, name: String, version: i32, sha256: String, size: u64, kind: LibraryKind, meta: Option<PrintMeta>, parsed: bool, has_preview: bool, uploaded_by: String, uploaded_at: i64`.
- `Config.library_dir: String` from `STARSTAR_LIBRARY_DIR`, default `"library"`.
- `LibraryStore::open(dir: &Path, pool: PgPool) -> Result<LibraryStore, StoreError>` (creates subdirectories, removes stale `tmp/*`, checks writability).
- `LibraryStore::add(&self, name: &str, kind: LibraryKind, uploaded_by: &str, body: impl Stream<Item = Result<Bytes, E>> + Unpin, expected_len: u64, max: u64) -> Result<(LibraryFile, bool /* created */), LibraryError>` — streams to `tmp/<random>`, hashes with SHA-256, fails on length mismatch (`LibraryError::Incomplete`) or over `max` (`LibraryError::TooLarge`), `fsync`s, renames into `blobs/…` (skip if present), parses (Task 1) and writes `thumbs/<sha>.png` once, then inserts in a transaction that takes `pg_advisory_xact_lock(hashtext(name))` and computes `version = max+1`; returns the existing latest row and `false` when its sha matches.
- `list(&self, q: Option<&str>, sort: LibrarySort) -> Result<Vec<LibraryFile>, StoreError>` — `LibrarySort { Newest (default), Name, SlicedFor }`; `q` matches `name ILIKE %q%`.
- `get(&self, id: i64) -> Result<Option<LibraryFile>, StoreError>`; `blob_path(&self, f: &LibraryFile) -> PathBuf`; `preview_path(&self, f: &LibraryFile) -> Option<PathBuf>`.
- `delete(&self, id: i64) -> Result<bool, StoreError>` — deletes the row; if no row still references the sha, removes the blob and preview (after the commit).
- `LibraryError { Incomplete, TooLarge(u64), Io(io::Error), Store(StoreError) }` → `ApiError` mapping: 400 / 413 / 500 / 500.
